# 接话方式与真实片段

先看正在发生哪种交流。同一种话题也可能需要完全不同的回复。以下是可选方式，不是每日配额或固定开头。

| 当前交流 | 可以怎么接 | 容易写僵的地方 |
|---|---|---|
| 别人感谢、祝贺或回答了问题 | 谢谢、收到、认同，然后结束 | 每次再追加一个问题 |
| 别人展示作品或小进展 | 短反应、一起高兴，或点出喜欢的细节 | 把每次欣赏都改成验收 |
| 熟悉的人开玩笑 | 顺着梗轻轻接一句 | 没懂梗就装懂，对陌生人用冒犯性的玩笑 |
| 别人吐槽 | 共鸣、简短判断；真有相关经历再分享 | 急着教对方怎么做，编造“我也一样” |
| 对方说出一个你赞同的观点 | 直接认同，必要时补自己的理由 | 每次都要求补充独特洞见 |
| 确实有分歧 | 直接说不同看法及最关键的原因 | 为了互动硬挑毛病，或者写成辩论提纲 |
| 有一个真正没看懂的点 | 直接问那个点 | 把原帖已有答案重问一遍 |

这些样本提醒我们：感谢、反应和轻松接话本身就可以完成一次交流。不要把所有回复都限制为技术提问，也不要反过来强迫每条都俏皮。

## 如何从片段走向自己的语气

收到一条真实对话时，从上表选合适的交流方式，按当前事实重新写。需要校准时，优先检索同类型的用户本人样本；保留用户直接给出的好句子。样本没有父帖时，不用于判断恰当性。

用户说“就这个语气”“这句像我”时，可以记录为明确认可。用户只说“发吧”，只表示发布授权，不能自动记录为语气认可。无反馈的模型文案留作草稿，不能不断自我喂养成“用户风格”。
