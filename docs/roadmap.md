# Mob Write 四阶段路线图

沿用已有仓库和实现推进，不重新维护一份源码。下表区分本轮候选验收与仍需后续证据的事项；完成一个阶段不代表已正式发版。

| 阶段 | 要交付什么 | 怎样验收 | 当前状态与未完成项 |
| --- | --- | --- | --- |
| 1. 定义宪法 | 简短原则、范围和四阶段计划 | 每条原则能指导具体写作或工程选择；明确事实、语言、私密数据、授权与价值验证边界 | 宪法与路线已写入本候选；后续变化应说明理由 |
| 2. 对齐当前实现 | Mob Write / `mob-write` 单入口，按需参考，旧调用兼容 | 名称、描述、路由、包与文档一致；根规则唯一；私密 profile 可选；升级可保留旧路径和拒绝危险覆盖 | 名称、单源、四入口及旧受管安装升级已验收；原仓库已原位改名 |
| 3. 验证发现、加载和写作价值 | 隔离安装、新会话实际读取、具体请求的写作对照 | 分开核对源/包/安装/读取；检查事实、承诺、收件人语言和多读/漏读；记录真实输出和试验限制 | 最终名称的 8 案试写和宿主/旧入口/保留目录切回已实测。仍有多读参考、无新信息播报及日期翻译边界；真实任务反馈、重复运行与其他宿主待验证 |
| 4. 做好安装升级与开源发行 | 可复现公开包、安装升级示例、迁移说明、CI 和审阅中的 PR | 从公开远端取得同一版本，隔离安装/升级、旧入口和 CI 产物一致；许可证完整，旧链接可核验 | 候选代码、安装示例、离线包与 42 项本地检查已完成；公开提交与 CI 状态见 [PR #2](https://github.com/hotmob/mob-write/pull/2) 的对应提交检查。合并及正式 release 待另作决定 |

## 本轮不做

- 不修改当前全局 skill、私人 profile 或其他项目，也不发送消息和控制社交账号。
- 不复制成第二个 canonical 仓库，不删除旧调用或复用旧仓库名破坏重定向。
- 不新增遥测、第三方推广、自动学习私人素材或平台基础设施。
- 不承诺写作提升百分比、真实使用人数或互动增长；现有合成对照不能支持这些结论。

后续优先解决观察到的加载混用、无用播报或事实失真问题，再考虑新增场景。真实任务反馈应由贡献者主动提供并去除私人信息；可使用本地方法，不要求上传自己的文字。验收证据见 [评估](evaluation.md)，安装边界见 [迁移](migration.md)。
