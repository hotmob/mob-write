# 中文写作

让读者直接读到意思、事实和行动。通用中文表达规则只在本 Skill 维护；个人 profile 只补充有依据的口吻差异。

## 选择范围

先根据用户的用途、读者、原稿和篇幅要求确定语域，已有上下文足够就直接写：

- 技术说明、手册和正式报告：结构清楚，术语准确；需要排版或文档组织时读取 [technical-document.md](references/technical-document.md)。
- 工作消息、邮件和普通文章：先给主要意思，再放必要依据或下一步；结构随内容决定。
- 微信、朋友圈和社交回复：保留自然口语、情绪、节奏及用户已有的语气词。短文本可以只有一两句，不加标题、总括段或技术手册结构。

输出本身需要中文写作时使用本方法，不把每个中文对话或专门的小说、剧本、翻译任务改造成写作审校；这些任务沿用用户指定的方法，只在明确要求润色时处理对应正文。用户要求逐字引用或仅改排版时，严格限于该范围。

## 写作与改写

1. 确定必须保留的信息：人物、对象、数字、时间、行动、条件、因果、承诺强度和情绪立场。改写时尤其保留否定、反问和“可能”“尚未验证”等限定的实际含义。
2. 直接表达实际情况，优先用具体动作、对象和结果。新写正文避免用“不是 A，而是 B”“不只是 A，更是 B”等人为对照制造洞见，也不拆成相邻短句绕过。真实纠错、比较或原稿有意的对照，可以保留必要的区分；不为避句式改掉用户立场或事实。
3. 删除没有新增信息的引导语、重复总结、口号和拔高。遇到“赋能”“闭环”“革命性”等词，写清机制或依据；确有专业含义时保留并解释。并列项和对比有实际信息时可用列表或表格。
4. 用常见现代汉语，明确指代，减少多层修饰和重复句式。长句按语义拆分，保留条件与结论的关系；不按字符数机械切碎。主动语态通常更直接，必要的被动、否定和专业表达可保留。
5. 让每段围绕一个意思，相关依据跟着判断。篇幅、标点、是否列点服从语域与阅读用途；不用强制的段落行数。

事实完整性是改写边界。不得新增无依据的数据、案例、引文、经历、评价或因果，不把推测写成已证实结果，不把计划写成已完成。样例只能作为表达参考，不能成为用户经历。代码、命令、路径、接口字段和原样引文保持精确。必要信息缺失时，省去该断言或提出一个关键问题；虚构示例需明确说明是示例。

## 叠加个人 profile

用户明确要求某人的口吻，或个人 profile 的准确触发场景成立时，再读取该 profile。通用层不自动假设作者是 Mob，也不自动读取私密语料。profile 可以调整用词、语气、节奏、选材和输出形态，不能替代本层或复制整套通用规则。

执行时先遵守当前系统约束与用户明确要求，再守住原意和事实边界，随后选择语域、应用本层，最后叠加个人偏好。显式的篇幅、正式程度和引用要求优先于 profile 的默认风格；语气可以个性化，事实与确定性不能随口吻改变。多层同时加载时按这套顺序协调，不反复互相调用。

本 Skill 无外部工具或其他 Skill 依赖。条件性技术参考缺失时，可完成不依赖该参考的文字润色，但需说明无法核验该项排版规范；用户要求完整规范审校时报告缺失，不凭记忆声称合规。指定 profile 缺失时仍可交付通用版本，并说明未应用该口吻；不要借用未经确认的样本。

## 交付

内部检查信息和承诺是否准确、语域是否适合、是否新增无依据内容、是否有重复套话。正式文档另查格式一致性。默认只交付可用正文；用户要求审查或修改说明时，再简要指出关键改动和不确定项。用户只要一版就给一版，候选数量与解释长度服从任务。起草不授权发送、发布或更新个人记忆。
